# منصة هندسة المنوفية · المنصة الأكاديمية

منصة تعليمية وتواصل أكاديمي متكاملة لكلية الهندسة – جامعة المنوفية، تجمع المواد الدراسية، المحادثات الفورية، التكليفات، تسليم الحلول، والتصحيح في مكان واحد، بواجهة عربية RTL مستوحاة من **Apple Liquid Glass**.

> النظام حقيقي بالكامل: قاعدة بيانات SQLite، مصادقة وجلسات آمنة، صلاحيات تُفحص على الخادم، رفع ملفات محمي، ومحادثات لحظية عبر SSE. لا توجد بيانات وهمية بعد التهيئة الأساسية.

## المتطلبات

- **Node.js 24 أو أحدث** (تم التطوير والاختبار على Node 26). يعتمد المشروع على وحدة `node:sqlite` المدمجة، لذا لا يحتاج أي قاعدة بيانات خارجية أو حزمة أصلية (native).
- **npm 10+**

تحقق من الإصدار:

```bash
node -v

```

## التشغيل السريع

```bash
# 1) تثبيت الحزم
npm install

# 2) تهيئة قاعدة البيانات بحساب المطور فقط (تلقائية عند أول تشغيل أيضاً)
npm run seed

# 3) تشغيل بيئة التطوير (API + الواجهة)
npm run dev
```

ثم افتح: **http://127.0.0.1:5173**

- الواجهة: `http://127.0.0.1:5173`
- الخادم: `http://localhost:4000`

```bash
npm run build     # بناء الواجهة إلى dist/
npm start         # تشغيل الخادم وخدمة الواجهة المبنية
```

ثم افتح: **http://localhost:4000**

## الحسابات والتهيئة

- **لا يوجد تسجيل ذاتي.** المطور فقط ينشئ حسابات الطلاب والدكاترة والمعيدين من لوحة الإدارة (اسم المستخدم، الاسم الكامل، الرقم القومي، كلمة المرور، نوع الحساب).
- عند أول دخول للطالب، يُوجَّه تلقائياً إلى صفحة **استكمال الملف الشخصي** (صورة + رقم هاتف + مراجعة البيانات) ولا يستطيع استخدام بقية المنصة قبل إكمالها.
- كلمة المرور تُخزَّن مجزّأة (bcrypt). الرقم القومي يُخزَّن مشفّراً (AES-256-GCM) مع بصمة HMAC لضمان التفرد، ويظهر مقنّعاً فقط (`301••••••••17`).
- يمكن للمستخدم تغيير كلمة المرور في أي وقت من صفحة الملف الشخصي.
- **نسيت كلمة المرور:** التحقق يتم باسم المستخدم + الرقم القومي، ويُعاد رمز استعادة لمرة واحدة (لا يوجد بريد إلكتروني في البيئة الحالية). يمكن للمطور أيضاً إعادة تعيين كلمات المرور.

### تهيئة بيانات تجريبية (اختياري)

```bash
npm run seed:demo
```

يضيف مواد ومعيدين وطلاباً وتكليفات ورسائل وتسليمات لتجربة المنصة كاملة. أمر `npm run seed` وحده ينشئ **حساب المطور فقط** ولا يضيف أي بيانات وهمية.

> لإعادة التهيئة من الصفر: احذف `data/elmanasa.db*` ثم شغّل `npm run seed`. ولتجربة البيانات: `npm run seed:demo`.

## أنواع الحسابات والصلاحيات

### المطور (Developer / Super Admin)

- إنشاء حسابات الطلاب والدكاترة والمعيدين وتعديلها وتعطيلها.
- إعادة تعيين كلمات المرور.
- إدارة كل المواد والمواد والتكليفات والإعدادات العامة.
- الوصول الكامل لكل البيانات والشاتات لأغراض الإشراف.
- إدارة الأدوار وعرض إحصاءات المنصة.

### الدكتور (Doctor)

- إنشاء مجموعات تعليمية للمواد (مع شات عام تلقائي).
- إضافة/تعديل/إزالة المعيدين وتحديد مواعيد السكاشن وصلاحيات النشر.
- إدارة الطلاب المسجلين وإزالتهم.
- إدارة الشات العام (فتح/إغلاق، الكتابة للجميع أو قراءة فقط).
- الإشراف على شاتات المعيدين، **وقبول/رفض طلبات انضمام الطلاب** إليها.
- إزالة طالب من شات معيد ليتمكن من اختيار معيد آخر.
- نشر تكليفات عامة أو خاصة بمعيد، وتحديد المواعيد والدرجات.
- مراجعة التسليمات وتصحيحها وإضافة الدرجات والملاحظات.

### المعيد (Teaching Assistant)

- الدخول للمواد التي أُضيف إليها فقط.
- إدارة شات السكشن الخاص به: قبول/رفض طلبات الانضمام، إعدادات الكتابة.
- تحديد موعد السكشن الخاص به.
- نشر تكليفات خاصة بشات طلابه، وتكليفات عامة فقط إذا سمح الدكتور.
- مراجعة وتسليمات طلابه وتصحيحها.

### الطالب (Student)

- استكمال الملف الشخصي عند أول دخول (إلزامي).
- استعراض كل المواد المتاحة والاشتراك/إلغاء الاشتراك.
- رؤية «موادي» وتفاصيل كل مادة.
- الشات العام للمواد المشترك بها.
- طلب الانضمام لشات معيد واحد فقط لكل مادة (لا يرى المحتوى قبل الموافقة).
- عرض التكليفات المتاحة له (العامة + الخاصة بشات معيده المقبول فيه).
- رفع الحلول (PDF/Word/صور/ZIP) ومتابعة الحالة والدرجة والملاحظات.

## البنية التقنية

### الخادم (Backend)

- **Node.js + Express 5**
- **`node:sqlite`** (قاعدة بيانات مدمجة، WAL، مفاتيح أجنبية مفعّلة)
- **bcryptjs** لتجزئة كلمات المرور
- **multer** لرفع الملفات مع قيود النوع والحجم
- **helmet** + **express-rate-limit** + فحص أصل الطلبات (CSRF origin check)
- جلسات بكوكيز `httpOnly` + `SameSite=Lax` + `Secure` في الإنتاج
- **SSE** (`/api/events`) للأحداث اللحظية (رسائل، إشعارات، تحديثات)
- مهمة دورية لتذكير مواعيد التسليم وتنظيف الجلسات المنتهية

### الواجهة (Frontend)

- **React 19** + **Vite 7** + **React Router 7**
- **lucide-react** للأيقونات
- CSS مخصص لنظام تصميم Liquid Glass (بدون Tailwind)
- خط **Tajawal** العربي، اتجاه RTL كامل، تصميم متجاوب

### هيكل المشروع

```

├── client/                 # واجهة React
│   ├── src/
```

## الأمان

- **كلمات المرور:** bcrypt مع ملح لكل مستخدم، ولا تُعاد أبداً في أي استجابة.
- **الأرقام القومية:** تشفير AES-256-GCM + HMAC-SHA256 للتفرد، وتُعرض مقنّعة فقط.
- **الجلسات:** رموز عشوائية تُخزَّن مجزّأة، وكوكي `httpOnly` لا يصل إليه JavaScript.
- **الصلاحيات:** تُفحص على الخادم في كل مسار (الملكية، الانضمام، نطاق التكليف، عضوية الشات). لا يكفي إخفاء الأزرار في الواجهة.
- **منع الوصول المباشر:** مسارات الملفات `/api/files/...` تتحقق من ملكية/صلاحية الملف قبل الإرسال؛ والطالب لا يستطيع قراءة شات معيد لم يُقبل فيه (403).
- **CSRF:** فحص أصل الطلب للطلبات المعدِّلة + SameSite=Lax.
- **الرفع:** أنواع MIME مسموحة محددة، حد أقصى للحجم (افتراضي 20MB)، وأسماء ملفات عشوائية على الخادم.
- **Rate limiting** على نقاط الدخول الحساسة.

## الإشعارات واللحظية

إشعارات داخل المنصة عند:

- نشر تكليف جديد، واقتراب موعد التسليم.
- طلب انضمام لشات معيد، وقرار القبول/الرفض.
- رسالة جديدة (مع دمج الإشعارات لتجنب التكرار).
- تغيير موعد السكشن، إضافة معيد، تعديل بيانات المادة.
- تسليم طالب جديد، إضافة درجة أو ملاحظة.
- إزالة طالب من شات معيد.

المحادثات تُحدَّث لحظياً عبر SSE، مع إعادة تحميل تلقائية للرسائل والإشعارات.

## المتغيرات البيئية

كلها اختيارية، والقيم الافتراضية مناسبة للتشغيل المحلي:

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `4000` | منفذ الخادم |
| `NODE_ENV` | — | `production` لتفعيل الكوكي الآمن وخدمة `dist/` |
| `APP_SECRET` | يُولَّد في `data/.secret` | سر تشفير الجلسات والأرقام القومية |
| `DATA_DIR` | `./data` | مسار قاعدة البيانات والسر |
| `UPLOAD_DIR` | `./uploads` | مسار الملفات المرفوعة |
| `MAX_FILE_MB` | `20` | أقصى حجم ملف بالميجابايت |
| `ALLOWED_ORIGINS` | — | قائمة أصول مفصولة بفاصلة للسماح بـ CORS |

> في الإنتاج، عيّن `APP_SECRET` قوياً واحتفظ به خارج المستودع.

## النشر على الإنترنت

لتشغيل المنصة على استضافة حقيقية يستخدمها أي شخص دون إبقاء جهازك مفتوحاً، راجع الدليل التفصيلي:

**➡️ [DEPLOY.md](./DEPLOY.md)**

يتضمن الخيار المجاني تماماً **Abasthan + Turso** (بدون بطاقة بنكية)، وخطوات Railway، وسيرفر VPS مع Nginx وHTTPS، والنسخ الاحتياطي، واستكشاف الأخطاء.

### ملخص سريع

1. استخدم **Abasthan + Turso** للحصول على استضافة مجانية بدون بطاقة: Abasthan يشغّل الموقع، وTurso يحفظ قاعدة البيانات والملفات.
2. في Abasthan اضبط: Node.js 22، و`npm ci --include=dev && npm run build` للبناء، و`npm start` للتشغيل، واختر خطة **Free**.
3. أضف المتغيرات: `NODE_ENV=production`، و`TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` من Turso، و`DEVELOPER_PASSWORD`، و`APP_SECRET` من ملف `elmanasa-deploy-values.txt`.
4. HTTPS مفعّل تلقائياً في Abasthan (إلزامي للكوكي الآمن و SSE).
5. عند أول إقلاع تُنشأ الجداول وحساب المطور تلقائياً من `DEVELOPER_USERNAME` و`DEVELOPER_PASSWORD`.
6. شغّل نسخة واحدة فقط (Replica = 1) لأن قاعدة البيانات لا تدعم كتابات متزامنة متعددة.
7. أضف متغير المستودع `APP_URL` في GitHub ليقوم ملف `keep-alive.yml` بفتح `/api/health` كل 10 دقائق.
8. احتفظ بنسخة احتياطية من Turso، ولا تشارك `APP_SECRET` أو `TURSO_AUTH_TOKEN` أو مجلدات `data/` و`uploads/` علناً؛ الوصول للملفات يمر عبر `/api/files/...` فقط.
